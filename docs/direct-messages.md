# 私信、好友收藏与后台内容管理

## 使用入口

- 点击聊天或心迹中的用户头像进入个人主页，可「收藏好友」或「发私信」。收藏是单向操作，不需要对方确认，也不是发送私信的前置条件。
- 自己的个人中心提供「私信」「好友收藏」两个分页。私信列出全部会话、最近消息与未读数，点击继续聊天；好友可按昵称或 ID 搜索，也可输入用户 ID 打开主页。
- 全站右上角个人头像显示未读红点。点击带红点的头像直接打开个人中心私信分页。
- 私信复用星球的文字、表情、图片、文件、表情回复、撤回和历史分页，使用独立的一对一界面，没有分享、邀请、成员管理、群投票或群游戏入口。
- 后台「全部私信」可搜索会话、只读查看双方完整历史与附件，不会加入会话或修改收件人的未读状态。
- 后台「心迹管理」分页查看全部心迹、媒体、语音、位置、点赞数和全部评论，可删除整条心迹或单条评论。删除整条心迹会清理其媒体和评论。
- 后台「漫游作品」显示关联分享链接；「相机分享链接」列出所有实际生成的链接，包括未关联审核记录的历史分享，并区分有效、过期、已删除。

## 数据与权限

私信、好友收藏和已读游标沿用 `SOUL_CHAT_DATA_FILE`（默认 `.data/soul-chat.json`），无需新增数据库或更改部署存储路径。保持现有数据版本，老星球兼容加载。

私信房间使用 `kind: direct` 和两个固定的 `participantKeys`。双方顺序不影响会话去重；稳定 publicKey 不随昵称、公开用户 ID 变更。普通星球列表、搜索和后台聊天室列表均排除私信。私信历史保留全部消息，不使用普通星球的 5,000 条截断规则。

Socket 服务沿用浏览器 UUID 身份体系，服务器从个人资料库解析用户，拒绝客户端伪造发送者、参与人或管理员权限。私信只允许固定双方加入、读取和发送；包括管理员在内的第三人不能加入。申请、邀请轮换、授权、新增成员和改成普通星球均在服务器拒绝。管理员通过独立的已认证 HTTP 接口只读查看，并记录 `direct.view` 审计。

未读消息按对方发送的消息和自己的已读游标计算。只有可见聊天页滚动到最新消息时才上报已展示的消息 ID；后台标签页、会话列表和管理员查看不会标记已读。消息时间戳严格递增，撤回后也不会复用，避免同毫秒分页漏消息或错误清除未读。游标和收藏持久化，Socket 通知同步当前用户的其他标签页；重连和恢复前台重新获取数据。

后台删除用户会同时删除其参与的私信会话、相关附件和好友收藏引用。新接口沿用后台登录、同源修改校验、禁止缓存及删除操作审计。

## 验证

`pnpm test:social` 使用隔离临时存储和真实 Socket.IO / Express 请求，覆盖会话去重、第三人拒绝、邀请/成员/改房间拒绝、伪造参与人、双向回复、收藏隔离、昵称变更、重启恢复、跨标签页未读、撤回、删除用户清理、后台认证、55 条消息历史分页、管理员查看不影响未读、心迹/评论删除和相机链接关联。

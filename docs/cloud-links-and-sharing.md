# 云传正文链接与发送后分享方案

## 目标

在云传普通正文中识别网页链接，保持原有文字外观，仅在悬浮或键盘聚焦时变色；发送成功后自动复制分享码，分享信息被长内容挤出可视区域时自动滚动并聚焦。JSON 解析弹窗不属于本次改动范围。

## 正文链接

- 保留原生 Ant Design `TextArea`，继续承担输入、选区、复制粘贴、撤销、字数统计、自动高度和清空操作。
- 在输入框上增加链接叠层，依据实际输入框尺寸、字体、行高、内边距及滚动位置同步布局。正文仍由原生输入框显示，叠层仅提供链接交互及悬浮色。
- 叠层按原生输入框的规则显示 CR、CRLF 和 LF 换行，避免历史文本末尾空行导致滚动错位；发送与复制仍使用未经改写的原文。
- 编辑时保留原生输入行为，鼠标点击不会误打开链接；输入框失焦后可点击 URL，在新窗口打开。链接支持 Tab 聚焦和键盘访问。
- 识别 `http://`、`https://`、`www.`，其中 `www.` 的访问地址补全为 HTTPS，显示文字保持原样。处理常见句末标点及不配对的闭括号，避免把正文标点带入链接。
- 使用 React 文本节点与 `<a>` 渲染，不解析 HTML，不使用 `dangerouslySetInnerHTML`；目标地址仅允许 HTTP/HTTPS，并设置 `noopener noreferrer`。

原始正文不被改写，发送、查询、历史记录和“复制内容”继续使用同一份原始文本。文件拖拽与上传、JSON 解析及其他操作保留原有流程。

## 发送后分享

- 仅在发送接口成功返回后递增专用成功序号。页面消费新序号处理定位，不监听密码变化，因此相同分享码重复发送仍可触发，查询和历史恢复不会误触发。
- 自动复制本次服务端返回的分享码快照，不复制分享链接。复制异步执行，不阻塞发送状态结束。
- 请求与历史记录使用发送开始时的正文快照，发送期间继续编辑不会把新草稿误记为已发送内容。
- 本地历史保存异常单独提示，存储超额、访问受限或旧记录损坏都不会把服务端已成功的发送误报为失败，也不会中断分享码复制和定位。
- 分享信息渲染后，根据滚动容器和实际可视区域检查位置；已可见时保持当前位置，越界时才滚动到底部分享区域并转移键盘焦点。尊重系统减少动态效果的设置。
- 定位前再次检查成功序号、密码和卡片显示状态；清空、隐藏或状态变化后，不执行过期定位。
- 优先使用 Clipboard API；不可用或失败时尝试临时只读输入框复制，并清理临时节点、恢复焦点和选区。两种方式均失败时提示用户手动复制，不把已成功的发送显示为失败。

## 边界

- 根据分享区域是否可见判断是否滚动，不设置固定“超长字数”阈值，以适应窗口大小、移动端及文件列表高度。
- 未带协议的普通域名、邮箱、文件路径和其他协议仍显示为普通文本；JSON 内容中的网页 URL 可作为普通正文识别，但不改变 JSON 解析功能。
- 浏览器权限、安全上下文或系统剪贴板限制可能阻止自动复制，此时保留手动复制入口和明确提示。
- 本次仅修改前端展示与发送成功后的交互；后端接口、传输数据、存储格式、分享码生成规则和有效期均不变。

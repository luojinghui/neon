# 云传广场需求

- 更新日期：2026-10-26
- 状态：功能已实现，已完成独立数据库与浏览器功能验收
- 需求来源：本次对话的初始需求与补充确认
- 现状依据：`src/app/cloud/`、`src/app/api/cloud/`、`src/server/models/cloud.js`、`src/components/topbar/`、`src/app/doodle/s/[shareId]/`

## 需求本质

在现有云传页面中增加匿名、公开、保留 48 小时的消息广场，供所有访问者发送和使用文字、图片与文件。每次发送形成一张内容卡片，并能通过固定链接直接访问该卡片。

## 目标与验收

1. 访问 `/cloud` 默认进入现有云传；原有查询码、文字和附件发送、查询、下载、历史、JSON 解析、分享链接与二维码等能力仍正常工作，历史分享地址 `/cloud?pwd=...` 继续可用，云传七天有效期不受影响。
2. 顶栏中部显示“云传 / 广场”两个 Tab。点击广场进入 `/cloud/plaza`；刷新、直接访问及浏览器前进后退后，选中项与实际路由一致。
3. 无需登录或查询码，访问者可查看并发送广场消息。纯文本、纯附件和混合内容均可发送；一次发送包含的全部内容始终属于一张卡片。
4. 发送成功后，当前页面输入区下方立即出现新卡片；失败时不出现成功卡片，并保留草稿与附件以便重试。
5. 卡片不显示姓名、头像或身份信息；正文可选择和复制，链接可打开，图片可查看，附件可下载。长文展开后仍处于原卡片内。
6. 任意访问者均可复制正文、下载附件、解析 JSON、分享以及删除整张卡片。没有正文编辑和附件增删入口。
7. 同一卡片多次分享得到相同链接，直接打开链接只显示对应卡片，不要求先进入广场或查询密码。
8. 卡片自服务端创建成功起有效 48 小时；到期后列表和分享页不再展示内容，新的附件访问请求失效。分享和查看不延长有效期。
9. 删除确认后，整张卡片及其附件均不可继续访问，已有分享链接随之失效。删除影响所有访问者。
10. 广场有手动刷新按钮，不进行自动轮询或实时推送；刷新不清空正在编辑的草稿或附件。

## 规则与异常

### 发送与展示

- 消息必须含非空白正文或至少一个附件，不能发送空卡片。
- 一次发送的内容或附件数量只影响卡片内部排版，不将其拆成多张卡片；这不表示文件体积或请求大小无限制，实施时沿用项目实际承载约束。
- 广场发送成功后清除已提交的草稿和附件，保留请求期间新增的未提交内容；发送失败保留输入。
- 广场没有查询密码输入、提取密码或发送后自动复制分享码的行为。
- 草稿清空只影响输入区；卡片删除只影响目标卡片。
- 正文按原文展示与复制，不把用户输入作为 HTML 执行。
- 合法 JSON 可查看结构、展开折叠、复制格式化结果；非法 JSON 保持普通正文展示。无正文的卡片不显示正文复制及 JSON 操作。

### 列表与刷新

- 初次进入获取列表，点击刷新重新获取最新首批内容；继续加载获取更早内容。
- 刷新期间保留输入草稿；刷新失败保留已展示列表并允许重试。
- 当前访问者发送或删除成功后，立即更新本地列表，无需再次点击刷新。
- 其他访问者的更改在重新进入、刷新或后续操作校验时体现；不主动实时同步。

### 固定链接与分享页

- 分享地址格式为 `/cloud/plaza/[messageId]`，同一卡片始终使用同一地址。
- 分享引用原卡片，不创建内容副本、不刷新到期时间。
- 分享页不显示列表和发送框，直接展示目标卡片的完整正文、图片及附件。
- 分享页提供复制正文、附件下载、JSON 解析、再次分享和整卡删除；删除需确认。
- 到期或已删除时统一展示“内容已过期或被删除”，提供“前往广场”入口。
- 网络或服务异常显示加载失败和重试，不误报内容已删除。
- 已打开的页面不接收远端删除通知；后续访问与操作以服务端最新有效状态为准。

### 删除与到期

- 删除确认文案明确：删除对所有人有效，相关附件与分享链接一并失效。
- 删除失败时不提前移除卡片；重复删除、已被他人删除或已过期时提示内容不可用并移除本地过期项。
- 有效期以服务端时间为准。到期后即使物理清理尚未完成，列表、详情和附件接口也必须拒绝访问。
- 定期回收过期或已删除内容的附件；清理失败保留重试依据。

## 约束与依赖

- 必须保持现有云传所有功能与旧分享地址兼容，不将原云传记录公开到广场。
- 使用现有 Next App Router、React、Ant Design、Zustand、MongoDB 与文件存储基础能力。
- 复用现有编辑器、文件选择/拖拽、图片查看、正文链接识别、JSON 查看和二维码展示能力。
- 广场数据与原云传数据隔离，原云传七天有效期与广场 48 小时有效期分别管理。
- 不依赖 Socket.IO 或前端刷新定时器。

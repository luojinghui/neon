# 云传广场设计

- 更新日期：2026-10-26
- 对应需求：`cloud-plaza-spec.md`
- 状态：功能已实现，独立数据库与浏览器功能验收完成

## 现状与影响

### 现状

- `src/app/cloud/page.tsx` 承载编辑器、查询结果、分享信息与弹窗，顶栏使用 `TopBar.middle` 展示标题及网络信息。
- `ContentEditor` 直接依赖 `useCloudStore` 和 `neonCloud`，输入、查询码、发送与分享状态耦合，不能直接作为第二套页面状态使用。
- `core.ts` 现有发送流程会获取查询码、保存本地历史、复制查询码、展示分享区域；广场不应调用这套发送成功逻辑。
- `CloudMessage` 要求查询码并使用七天有效期与 MongoDB TTL；现有附件记录由 `/api/cloud/file/[fileId]` 下载。
- JSON 弹窗、二维码弹窗以及文件列表读取云传全局状态，需要抽出可接收参数的展示层才能安全用于广场。
- 项目已有单内容分享页、图片查看器、主题和卡片样式，可作为复用依据。

### 要改

| 模块 | 设计 |
| --- | --- |
| 云传顶栏 | 增加共享的路由 Tab 导航，居中显示“云传 / 广场”；保留网络信息可用与现有左右操作 |
| 输入组件 | 抽出接收草稿、附件、操作回调的通用编辑器；云传用适配层保留现有行为，广场接入自己的状态与发送函数 |
| 展示组件 | 复用正文链接识别和图片查看，抽出参数化 JSON 弹窗；广场列表和分享页共用卡片、附件及二维码分享展示 |
| 广场页面 | 新增独立页面、状态管理、客户端请求、卡片列表与刷新入口 |
| 分享页面 | 新增单卡片路由，复用广场卡片展示及操作 |
| 服务端 | 新增广场消息模型、列表/发送/详情/删除/附件接口及文件回收逻辑 |

### 不改

- `/cloud` 默认入口与 `/cloud?pwd=...` 既有分享地址。
- 原有 `/api/cloud`、`/api/cloud/file/[fileId]` 的请求与响应契约。
- 原云传查询码生成规则、七天有效期、既有数据和文件可见性。
- 原云传发送后的查询码复制、历史记录、分享展示和定位行为。
- Socket.IO 连接、消息协议及其他页面功能。

## 架构与职责

### 路由

| 路由 | 职责 |
| --- | --- |
| `/cloud` | 默认云传页，保留密码发送与查询 |
| `/cloud/plaza` | 广场输入、列表、手动刷新及加载更多 |
| `/cloud/plaza/[messageId]` | 对应卡片的独立分享页 |

使用 Next Link 切换，依据路径高亮 Tab，支持直接访问与浏览器历史。分享页使用“广场分享”标题与“前往广场”入口，不渲染双 Tab 或编辑器。

### 数据与状态

- 新增独立 `CloudPlazaMessage` 集合，字段包含 `messageId`、`content`、`files`、`createdAt`、`expireAt`；删除与清理如需重试，可增加 `deletedAt` 等内部状态。
- 不存储供展示的作者资料，不需要查询码，不复用原云传消息集合。
- 附件元数据沿用 `fileId/fileName/fileSize/mimeType/relativePath/storagePath` 结构，物理文件放在独立的 `upload/cloud-plaza/` 下。
- 广场客户端状态包含草稿、待发送附件、发送进度、卡片列表、分页游标、刷新/加载状态及独立的 JSON/分享弹窗状态。
- 云传和广场使用各自 feature 内的 Zustand 状态，客户端路由切换时保留草稿且不混用。只要求当前会话内保留，不将大文件写入浏览器持久化存储。
- 原云传历史记录行为保持不变。广场输入历史可复用界面与读写逻辑，但使用独立存储键，避免两个入口的草稿历史相互覆盖。

### 生命周期

- 创建时由服务端设置 `expireAt = createdAt + 48 小时`；客户端不能指定或延长。
- 查询、详情、下载和删除入口统一校验有效状态及过期时间。
- 统一清理任务负责过期和删除记录对应的文件，失败可重试；不能仅靠 MongoDB TTL 删除记录而丢失文件清理依据。
- 删除先使记录不可访问，再回收附件；清理成功后删除内部记录，避免文件删除失败使卡片重新可用。
- 分享链接直接由消息 ID 生成，不另建分享副本，也不增加分享生命周期。

## 关键流程与契约

### 广场页面布局

1. 顶栏：居中的“云传 / 广场”Tab，默认选中云传；原有返回首页、网络信息、主题及账号快捷入口保持可用。窄屏保证 Tab 与两侧控件不重叠。
2. 输入区：沿用现有编辑器样式与输入功能，广场隐藏查询码控件，增加简短提示“公开可见，48 小时后自动清理”。
3. 列表标题行：左侧“广场”，右侧“刷新”按钮；刷新时展示 loading 并避免重复提交。
4. 内容区：纵向卡片列表，最新在前。每张卡片内依次为正文、图片、文件和操作区。
5. 列表底部：加载更多、已加载完、空状态或失败重试。

卡片以内容为主：正文保留原始换行，链接沿用现有识别规则；长文展开、多附件收起都在同一张外层卡片内完成。图片点击进入查看器，文件按名称、路径、体积展示下载操作。没有正文时隐藏正文复制和 JSON 按钮。

### 分享页布局

沿用云传的背景、面板、圆角、主题和响应式宽度，桌面使用居中单列阅读布局，手机铺满可用内容宽度。

页面自上而下：

1. 顶栏左侧“前往广场”，中间“广场分享”，右侧主题切换。
2. 一张内容卡片：顶部弱化展示发布时间、到期时间；正文默认完整展示，长文本由页面自然滚动；图片与全部附件仍属于同一张卡片。
3. 卡片操作区：复制正文、JSON 解析、分享；删除置于次级操作位置。文件下载入口在各附件旁。
4. 卡片底部轻提示：“公开内容 · 发布后 48 小时自动失效”。

分享页不要求存在上一页历史，浏览器新窗口直接打开也能查看。无发布者姓名与头像，无输入框或其他卡片干扰。

分享面板展示固定链接、复制链接按钮和二维码，列表与分享页共用同一面板。正文只在对应卡片中展示，分享面板不重复复制正文内容。

页面状态：

- 加载中：卡片骨架或局部 loading。
- 内容有效：显示单卡及允许的操作。
- 已删除/已过期/不存在：显示“内容已过期或被删除”和“前往广场”。
- 地址格式错误：显示“分享链接无效”和“前往广场”。
- 服务异常：显示“加载失败”、重试及前往广场入口。

### 接口

| 接口 | 输入 | 输出/行为 |
| --- | --- | --- |
| `GET /api/cloud/plaza` | 可选分页游标与页大小 | 有效卡片列表、下一页游标、服务端时间 |
| `POST /api/cloud/plaza` | 纯文本 JSON，或含 `text/files/relativePaths` 的 FormData | 完整新卡片，含固定 ID、创建时间、到期时间 |
| `GET /api/cloud/plaza/[messageId]` | 消息 ID | 单个有效卡片或不可用状态 |
| `DELETE /api/cloud/plaza/[messageId]` | 消息 ID | 删除整卡，立即阻止详情及附件访问 |
| `GET /api/cloud/plaza/file/[fileId]` | 附件 ID | 校验所属卡片有效后返回文件；按查看/下载场景设置响应头 |

卡片公开响应包含 ID、原始正文、附件公开元数据、创建和到期时间，不返回物理文件路径或内部清理状态。排序以 `createdAt` 和 `messageId` 为稳定顺序，分页避免并列时间导致跳项。

列表、详情、分享页面及附件访问采用适当的动态渲染与禁止缓存策略，避免删除后仍由应用或浏览器缓存提供有效内容。已经被访问者复制或下载的内容不属于服务器可回收范围。

### 发送

1. 捕获本次提交的正文和附件快照，校验非空，防止重复点击。
2. 纯文字走 JSON，附件走上传请求并展示进度。
3. 后端写文件与记录；失败时回收本次未完成文件，避免孤立文件。
4. 成功返回完整卡片，按 ID 合并到列表顶部并去重；只清理已提交内容，保留发送期间的后续修改。
5. 失败保留草稿和附件并提示重试；不复用原云传复制查询码或展示分享信息的发送后逻辑。

### 刷新与分页

- 初次进入加载第一页；用户点击刷新重新获取第一页并重置后续游标，不改变草稿和附件。
- 用户点击加载更多时使用游标获取更早卡片，按消息 ID 去重。
- 刷新期间保留旧列表，失败提示后可重试。处理并发返回顺序，过时请求不得覆盖更新的列表或重新加入已删除卡片。
- 不建立实时订阅、不轮询，也不在窗口重新聚焦时自动刷新。
- 可以依据已知到期时间在本地隐藏到期卡片；这不触发网络刷新。服务端校验始终是最终依据。

### 查看、JSON 与复制

- 复制正文保留原文；复制格式化 JSON 使用解析结果，不修改原文或服务端内容。
- JSON 查看器接收显式的原始内容/解析值，不借用云传当前草稿；兼容合法 JSON 的对象、数组和标量，不能用值的真值判断是否可展示。
- 图片查看及附件下载校验卡片有效状态。操作发现失效时，在列表移除对应项或将分享页切到不可用状态。
- 剪贴板失败提供可手动复制的明确反馈，不将服务端已成功操作误报为失败。

### 删除

1. 弹出确认：“删除这张卡片？所有人将无法继续查看，附件和分享链接也会失效。”
2. 调用删除接口，服务端先将记录设为不可访问，再执行可重试的附件回收。
3. 成功后移除本地卡片；在分享页删除则原地进入不可用状态。
4. 已删除或已过期按幂等不可用状态处理；网络/服务失败保留当前卡片并允许重试。
5. 其他已打开页面不主动刷新，下一次访问或服务端操作校验反映最新状态。

## 测试关注点

- 云传完整回归：默认路由、旧查询链接、查询码、纯文本/纯文件/混合发送、文件和文件夹、图片粘贴、上传进度、历史、清空、JSON、密码复制、分享链接、二维码及发送后定位。
- 两个 Tab 切换、浏览器前进后退、直接访问与草稿隔离；广场不能触发云传的查询码或分享成功逻辑。
- 匿名查看、发送、复制、下载和删除；一次发送始终一张卡片，纯附件与长文/多附件布局正确。
- JSON 对象、数组和标量的解析、复制与错误处理；多个卡片和草稿互不串内容。
- 相同卡片分享多次得到相同链接；新浏览器直接打开分享页；分享不延长有效期。
- 删除和 48 小时到期同时约束列表、详情、分享和文件请求；物理清理失败仍不可访问，并能再次回收。
- 无自动刷新请求；手动刷新、分页、并发返回、发送中编辑和删除后的本地状态保持正确。
- 桌面/手机、明暗主题、顶栏无重叠、长正文阅读、图片查看、无内容/失效/加载失败状态。

## 待明确事项

无阻塞项。默认云传、兼容现有功能、禁止编辑与附件增删、固定链接分享和手动刷新已实现。

## 实现与运维

- `src/server/models/cloudPlaza.js` 与 `src/server/cloud/plazaRepository.js` 管理独立集合、48 小时有效期、附件存储和清理，不迁移或公开原云传记录。
- `src/app/api/cloud/plaza/` 提供列表、发送、详情、删除和附件访问。
- `src/app/cloud/plaza/` 提供广场、卡片、独立草稿及单卡分享页；`ContentEditorView` 和 `JsonViewerModal` 为可复用展示组件。
- 没有新增运行依赖；`package.json` 仅增加 `test:cloud` 命令。
- 附件默认存储在 `upload/cloud-plaza`，可通过 `CLOUD_PLAZA_UPLOAD_DIRECTORY` 指向发布目录外的持久化位置，示例见 `.env.example`。
- 启动服务时执行一次过期清理，其后每 15 分钟清理一批过期或已删除内容，失败记录保留重试；所有读取接口独立检查到期时间。部署新代码后需要重新构建并重启 Node 服务。
